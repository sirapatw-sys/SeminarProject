# แก้การเลือกบริบท NPC หลังตรวจงาน

ต่อจาก `0897dba` ในสาขา `codex/npc-cothinking` แก้เฉพาะตัวเลือกบริบทและเพิ่ม regression ไม่เพิ่มฟีเจอร์ ไม่เปลี่ยน provider/model/key และไม่เรียก API จริง

## ปัญหาที่ตรวจยืนยัน

ผลตรวจที่ `Logs/NpcReviewAudit_20261017/Diagnostics.xml` ยืนยันกรณีใหม่ 4 กรณี: คำขอ "พิจารณาภาพวาดให้ที" มี action เป็นศูนย์จน NPC ไม่ลงมือ แม้ provider จำลองตีความถูก; ข้อความคุยเล่นอีก 3 ประโยคกลับแนบ action 34 รายการ

ชุดเดิมด้าน world commands ในการตรวจนั้นผ่าน 62/62 ไม่ใช่การรันชุดเต็ม 1,659 ซ้ำ ผลตรวจเก่าทั้งหมดเก็บเป็นประวัติ ไม่ใช้แทนผลหลังแก้รอบนี้

## วิธีแก้

- เลือกเป้าหมายจากวัตถุที่มีอยู่ก่อน ไม่บังคับว่าข้อความต้องมีคำกริยาจากรายการเดิม จึงเสนอ inspect ให้ "พิจารณาภาพวาดให้ที" หรือ "Assess the painting for me" ได้
- เมื่อไม่ได้ระบุวัตถุ ใช้รูปประโยคคำขอ/คำลงท้ายขอให้ช่วยและตัวอ่านคำสั่งเดิม ไม่ใช่การพบคำว่า "ดู" หรือ "ช่วย" ที่ไหนก็ได้ในประโยค
- คำขอแบบอ้างสิ่งของด้วยคำบรรยายที่ยังไม่มีชื่อชัดเจนยังมีรายการวัตถุแบบย่อให้ AI พิจารณา ไม่เดาตำแหน่งหรือเป้าหมายให้เอง
- การเสนอ capability ไม่ใช่อนุญาตให้ลงมือ ทุกผลจาก AI ยังผ่าน semantic executor, กฎคำปฏิเสธ/คำถาม/เป้าหมาย และสิทธิ์ปริศนาเดิม ผู้เล่นยังต้องลงมือค้นพบหลักฐานหลักเอง
- ไม่เพิ่มการเรียก AI แยกอีกครั้งเพื่อจำแนกเจตนา จึงไม่มี network round-trip เพิ่มจากการแก้นี้

## ขนาด prompt ที่วัดแบบออฟไลน์

Room01 ใหม่ ความสัมพันธ์เริ่มต้น บริบทเสริมว่าง ใช้ BuildReplyPrompt จริง ไม่ใช่ token หรือ usage จาก KKU

| ข้อความ | action ก่อน → หลัง | prompt ตัวอักษรก่อน → หลัง |
| --- | ---: | ---: |
| วันนี้เธอดูเหนื่อยนะ | 34 → 0 | 10,995 → 2,890 |
| ขอบคุณที่ช่วยนะ | 34 → 0 | 10,990 → 2,885 |
| อยากให้เราช่วยอะไรไหม | 34 → 0 | 10,996 → 2,891 |

บริบทและประวัติจริงอาจทำให้ขนาดต่างออกไป ระบบนี้ไม่ได้รับประกันว่าทุกประโยคของทุกโมเดลตีความได้ถูกต้องทั้งหมด แต่ไม่ตัดความสามารถเพียงเพราะใช้คำกริยาต่างจากรายการเดิมเมื่อระบุเป้าหมายแล้ว
