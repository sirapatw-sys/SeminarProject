## ลองเล่น

ตัวเกม Windows รุ่นก่อน (12 ตุลาคม 2026) (แก้ Alice เดินค้างใกล้เฟอร์นิเจอร์ พร้อมการซ่อนข้อความค้างและเดินช้าลง) อยู่ที่ `Logs/Room01CompanionNavigationFix_20261012/Windows/MysteryGame.exe` เปิดแล้วเลือกเริ่มเกมใหม่เพื่อเข้าห้องแรก ถ้าจะย้ายเครื่อง ต้องคัดลอกทั้งโฟลเดอร์ `Windows` ไม่ใช่เฉพาะไฟล์ `.exe` ตัวเกมนี้ยังไม่ได้ส่งขึ้น GitHub ไฟล์ตัวเกมในโฟลเดอร์รุ่นเก่าไม่ได้เปลี่ยนตาม

ภาพรวมงานที่เพิ่มหลัง branch เพื่อนและสถานะส่งต่ออยู่ใน [ROOM01_COMPANION_PROGRESS_TH.md](ROOM01_COMPANION_PROGRESS_TH.md)

1. ใช้ branch `codex/room01-companion` ใน Unity 2021.3.16f1 เปิด `Assets/Scenes/Room01.unity` แล้วกด Play / เริ่มเกม
2. เข้าใกล้ Alice กด **E** แล้วพิมพ์คำชวนเอง เช่น “เดินไปด้วยกันไหม” หรือ “ตามเรามาหน่อย” ไม่ต้องเลือกปุ่มคำสั่ง และไม่มีแผงสอนเล่นค้างมุมขวา
3. ปิดบทสนทนาแล้วลองเดินสำรวจพร้อม Alice เธอจะเคลื่อนไหวตามและหลบสิ่งกีดขวาง ไม่เทเลพอร์ต ถ้าอยากให้รอ เข้ามาคุยแล้วพิมพ์ “รอตรงนี้ก่อน” หรือ “หยุดตามก่อน”
4. ไปที่ **กล่องสองมือ** กลางห้องด้านล่าง ชื่อกล่องจะขึ้นเฉพาะเมื่อเข้าใกล้ เข้าใกล้ Alice แล้วพิมพ์ “ช่วยเราเปิดกล่องสองมือในห้องนี้หน่อย” ปิดบทสนทนา Alice จะเดินไปจุดสีฟ้า ผู้เล่นยืนจุดสีทองให้ครบ **3 วินาที** หากเดินออกก่อน เวลาจะเริ่มใหม่ จุดสีและเปอร์เซ็นต์ขึ้นเฉพาะกิจกรรมที่กำลังช่วยและอยู่ใกล้ เมื่อสำเร็จแล้วไม่มีป้ายค้าง
5. เมื่อสำเร็จ กล่องเปลี่ยนเป็นเปิด มีบทพูดตอบรับ ความสัมพันธ์ +3 และความทรงจำร่วมในสมุด **J** คุยกับ Alice อีกครั้งจะมีคำทักเกี่ยวกับสิ่งที่ทำด้วยกัน (เมื่อความสัมพันธ์มากกว่า 35)
6. ลองสำรวจภาพวาด โต๊ะ และเปิดลิ้นชักขณะ Alice อยู่ใกล้ จะมีปฏิกิริยาสั้น ๆ ตามผลการกระทำจริง ไม่ต้องเปิดบทสนทนาและไม่หยุดการเดิน
7. ถ้าพิมพ์ “กล่องสองมือเปิดยังไง, ช่วยเราหน่อย” จะตอบวิธีเฉย ๆ ไม่เริ่มงาน ไม่แจกคำใบ้ภาพวาดแทน คำถามสถานะ คำปฏิเสธ ข้อความสมมติ หรือคำพูดในเครื่องหมายอัญประกาศไม่ถือเป็นคำสั่ง หากถามปริศนาหลักร่วมด้วยยังใช้สิทธิ์คำใบ้ตามความสัมพันธ์
8. พิมพ์ให้กำลังใจ เช่น “ไม่ต้องกลัวนะ เราอยู่ด้วย” เพื่อสร้างความทรงจำและลดคิดถึงบ้าน ได้รางวัลครั้งเดียวต่อเซฟ ไม่ใช่ปุ่มเพิ่มคะแนนซ้ำ
9. ลองคำถาม “เธอช่วยเปิดกล่องสองมือแล้วใช่ไหม” / “เธอตามเรามาเหรอ” / “ช่วยสอนฉันเปิดกล่องสองมือหน่อย” จะไม่เริ่มงานเอง ส่วน “ช่วยเปิดกล่องสองมือได้ไหม” ยังเป็นคำชวนให้ช่วยจริง
10. คำเกริ่นใช้ได้ เช่น “ช่วยหน่อย, ตามเรามาหน่อย” หรือ “ช่วยเราหน่อย, รอตรงนี้ก่อน” ไม่หลุดเป็นคำใบ้ปริศนา หากขอคำใบ้ปริศนาหลักอย่างชัดเจนร่วมด้วย ยังใช้ระดับความสัมพันธ์เดิม
11. ขณะ Alice เดินตาม ลองพิมพ์ “เธอตามเรามาเหรอ, รอตรงนี้ก่อน” เธอจะรับคำขอให้รอ ไม่ให้คำถามในวรรคแรกกลบคำขอวรรคหลัง ส่วน “เธอตามเรามาอยู่หรือเปล่า” และ “เธอช่วยเปิดกล่องสองมือไปแล้วรึเปล่า” เป็นคำถามสถานะ ไม่เริ่มเดินหรืองานใหม่
12. “เธอตามเรามา, ใช่ไหม” เป็นคำถาม ไม่เริ่มเดิน และ “ช่วยเปิดกล่องสองมือหน่อย, ไม่เอาแล้ว” ถอนคำขอที่อยู่ในข้อความเดียวกัน ไม่เริ่มงาน หากพูดต่อว่า “ตามเรามาหน่อย, ไม่ต้องแล้ว, รอตรงนี้ก่อน” จะรับเฉพาะคำขอให้รอที่เหลืออยู่ การถอนคำขอแบบนี้ไม่ใช่คำสั่งยกเลิกงานจากข้อความก่อนหน้า ถ้ากำลังช่วยอยู่ให้พูด “รอตรงนี้ก่อน” เพื่อหยุดงาน

ไม่ต้องใส่ API key เพื่อเล่นระบบนี้ บทพูดสั้นและผลการกระทำกำหนดโดยเกม หากเปิดใช้ AI ตามปกติ ระบบจะส่งสถานะเพื่อนและความทรงจำที่เกมยืนยันไปประกอบบทสนทนา แต่ AI ไม่ใช่ผู้ตัดสินว่าช่วยงานสำเร็จหรือไม่

## จุดแก้หลังตรวจต้นแบบ

- เอาแผงสถานะ/ข้อความสอนเล่นที่ค้างมุมขวาออก ชื่อกิจกรรมขึ้นเมื่ออยู่ในระยะ 2.4 หน่วยเท่านั้น จุดสีเป็นวงเล็กไม่มีตัวหนังสือและขึ้นเฉพาะตอนร่วมมือ กิจกรรมสำเร็จแล้วซ่อนป้าย แต่ยังเห็นภาพกล่องเปิด บทพูดเหนือ NPC เป็นข้อความชั่วคราว ไม่บังคับเปิดบทสนทนา
- ลดความเร็ว Alice จาก 4.4 เป็น 2.6 หน่วย/วินาที เร่งและผ่อนความเร็ว ปรับเส้นทางลัดเฉพาะเมื่อทั้งเส้นและก้าวจริงไม่ชน มีระยะเริ่มตามใหม่ห่างกว่าระยะหยุด 0.45 หน่วย ลดการขยับถี่ขณะผู้เล่นยืนอยู่ใกล้ เมนู/คำชวนให้รอ/โหลดเซฟล้างความเร็วค้าง
- ลดจังหวะอนิเมชันเดินและความสูงเด้งเฉพาะ Companion ให้ตามความเร็วจริง ไม่เปลี่ยนความเร็วหรือจังหวะเดินของผู้เล่น/NPC ที่ไม่ได้เปิด Companion
- คำถามยืนยันหลังเครื่องหมายจุลภาคย้อนกลับไปขยายวรรคก่อนหน้า ไม่ปล่อยให้คำสั่งทำงานก่อนอ่าน “ใช่ไหม” ส่วนการถอนคำขอจะล้างคำขอที่ยังรออยู่ในข้อความนั้นก่อนตัดสิน รวมกรณีที่คำขอเดิมขัดกัน แต่ยังรับคำขอใหม่ที่พูดต่อได้
- เครื่องหมายอัญประกาศตรวจหลังปรับ Unicode และลบอักขระซ่อนแล้ว เพื่อไม่ให้เครื่องหมายเต็มความกว้างหรืออักขระท้ายข้อความทำให้คำพูดอ้างอิงกลายเป็นคำสั่งจริง
- คำอ้างผลสั้น ๆ เช่น “งานเสร็จแล้วค่ะ” / “ตอนนี้เสร็จแล้วค่ะ” / “ฉันช่วยแก้ให้เสร็จแล้ว” ไม่ผ่านเมื่อไม่มี fact ยืนยัน ทั้งแชท บท mini-event และคำตอบหลังเลือกตัวเลือก การแนบ fact ที่ถูกต้องแยกบรรทัดไม่รับรองคำอ้างที่แต่งเพิ่ม
- สำนวนสังคม “We're done talking for today.” และ “I'm holding back tears.” ผ่านได้ แต่ยังตรวจคำอ้างผล ชื่อกิจกรรม และรหัสในข้อความส่วนอื่นตามเดิม ไม่เว้นทั้งข้อความเพียงเพราะมีสำนวนที่อนุญาต
- แยกคำถาม/คำสอน/คำถามสถานะออกจากคำขอลงมือเป็นรายวรรค รับคำขอชัดเจนที่เหลือเพียงอย่างเดียว คำขอสองอย่างที่ขัดกันจะขอให้ชวนทีละอย่าง ไม่เลือกทำอย่างแรกเอง
- ตรวจว่าคำขอเริ่มด้วยคำชวนที่รองรับและผูกกับชื่อกิจกรรมจริง “ช่วยทุบกล่อง” ไม่ถูกแปลเป็นช่วยเปิดกล่อง ส่วนคำพูดอ้างอิง สมมติ และเครื่องหมายอัญประกาศยังไม่รันคำสั่ง
- บทคุยความรู้สึก เช่น “หายกังวลแล้ว” / “กล้าขึ้นแล้ว” / “เชื่อใจได้แล้ว” ผ่านได้โดยไม่ใช้รายชื่ออารมณ์สั้น ๆ เป็นข้อยกเว้น แต่ยังตรวจรหัสและคำอ้างผลกิจกรรมในข้อความทั้งหมด
- คำอ้างผลแบบ passive หรือไม่ระบุสิ่งของ เช่น “It has already been opened for you.” / “We are finally done.” / “ฉันจัดการให้เรียบร้อยแล้ว” ต้องใช้ fact ที่ยืนยันได้เช่นเดียวกับคำอ้างผลตรง ๆ การแนบ fact ที่ถูกต้องบนอีกบรรทัดไม่รับรองคำอ้างที่ AI แต่งเพิ่ม
- แยกคำถามยืนยันสถานะและคำขอให้สอนออกจากคำชวนลงมือทำ ไม่ห้ามคำถามทั้งหมดจนคำขอสุภาพใช้ไม่ได้
- เก็บคำเกริ่นขอความช่วยเหลือแยกจากคำขอคำใบ้ที่ระบุชัด เป้าหมายกิจกรรมในวรรคถัดไปแก้ความหมายคำเกริ่นได้ แต่ไม่ลบคำถามปริศนาหลักหรือคำขอคำใบ้จริง
- ปฏิเสธคำอ้างผลสำเร็จที่ไม่มี fact ทั้งใน chat และ mini-event รวม `have already`, `just`, คำอ้างผลที่ละประธาน และ “ทำให้เรียบร้อยแล้ว” โดยยังรับสำนวนความรู้สึก “ทำให้ฉันรู้สึกดีขึ้นแล้ว” และ “opened up”

- สถานะกิจกรรมมี factId แยก `pending` / `completed` ตาม GameState ส่วนโหมดเดินตาม/รอ/ช่วยอ้างจากตัว NPC จริง AI ใช้ `{fact:factId}` บนบรรทัดแยก เกมเติมข้อความสถานะเอง ไม่ยอมรับ fact ของสถานะที่ยังไม่เกิด
- ตัวกรองปฏิเสธข้อความ AI ที่แต่งผลกิจกรรมด้วยชื่อ/ชื่อเรียกอื่นที่ตั้งไว้ และรูปประโยครายงานการกระทำ เช่น “ฉันเปิดให้แล้ว” ทั้งในแชทและ mini event โดยไม่เพิ่มสิทธิ์คำใบ้ ข้อความสังคม/ความรู้สึกยังเขียนตามบุคลิกได้
- รหัสผิดที่ใส่ครบในคีย์แพดส่งผลการลองจริงให้ Alice รับรู้ หน้าคีย์แพดยังเปิดอยู่ให้ลองใหม่ การใส่ไม่ครบหรือกดปิดไม่ถือว่าล้มเหลว
- สำรวจลิ้นชักที่เปิดแล้วไม่สร้างความทรงจำว่าผู้เล่นเปิดไม่สำเร็จ ส่วนการลองใช้วัตถุที่ยังติดเงื่อนไขยังนับเป็นความพยายามที่ไม่สำเร็จตามเดิม
- พิมพ์ชวนช่วยกิจกรรมเดิมซ้ำไม่ล้างความคืบหน้า ไม่ต่อเวลา และไม่ลืมว่าก่อนช่วยเคยเดินตาม เมื่อสลับงานยังจำการเดินตามเดิม แต่ชวนให้รอจะยกเลิกเจตนานี้
- การเดินตามหาเส้นทางไปหาผู้เล่นแล้วหยุดในระยะที่กำหนด ไม่ยึดจุดเยื้องเพียงจุดเดียวที่อาจอยู่ในโซฟา จุดเริ่ม/ปลายทางนอกตารางเชื่อมกับจุดใกล้เคียงที่เดินได้ ตรวจการชนตลอดทางและจำกัดขนาดการค้นหา/ความถี่คำนวณเหมือนเดิม
- คำชวนที่ชัดเจนเริ่มคำสั่งที่เกมอนุญาต: เดินตาม / รอ / ช่วยกิจกรรมที่ระบุชื่อ / รับกำลังใจ ไม่เรียก provider และไม่ให้ AI ตัดสินผลสำเร็จ คำถามวิธีหรือสถานะยังเป็นการตอบข้อมูลเท่านั้น เมื่อทำสำเร็จแล้วจะไม่เริ่มกล่องเดิมซ้ำ
- ตรวจจุดหยุดและเส้นทางที่ตัดให้สั้นจริงอีกครั้ง หากจุดนั้นชนเฟอร์นิเจอร์จะหาเส้นทางตารางไปจุดอื่นในระยะหยุด ไม่ใช้จุดชนเดิมซ้ำทุกเฟรม
- ตัวกรองปฏิเสธคำอ้างผลที่ไม่มีหลักฐาน เช่น “ฉันเปิดให้เรียบร้อยค่ะ” และ “I've opened it for you.” แต่ยังอนุญาตสำนวน “เปิดใจ” / “opened up”
- ตัวกรองยอมรับสำนวนสังคม เช่น “เปิดใจ” “กำลังจับใจความ” “กำลังยืนยัน” และ “opened up” โดยยังตรวจชื่อสิ่งของ รหัส คำสั่งสำรวจ และคำอ้างผลกิจกรรมในข้อความส่วนที่เหลือ

## ขอบเขตและกติกา

- กล่องสองมือเป็นกิจกรรมเสริม ไม่มีรหัส กุญแจ หรือเงื่อนไขใหม่สำหรับประตู เส้นทางเดิมยังเป็น ภาพวาด → โต๊ะ/โน้ต → ลิ้นชัก → กุญแจ → ประตู
- ไม่ต้องมีความสัมพันธ์สูงก่อนร่วมมือ ไม่เพิ่มระดับคำใบ้เพื่อแลกกับการช่วยงาน
- รางวัลกล่องและการให้กำลังใจ (+1, ลดคิดถึงบ้าน 10) ได้ครั้งเดียวต่อเซฟ พิมพ์ชวนซ้ำไม่สะสมคะแนนเพิ่มจากคำสั่ง
- การเปิดบทสนทนา เมนู สมุด หรือหน้าต่างตั้งค่าจะพักการเคลื่อนไหวและเวลาช่วยงาน ไม่เด้งบทสนทนาขัดการเล่น
- ถ้าไปไม่ถึงหรือรอนานเกิน 45 วินาทีของเวลาเล่นจริง Alice จะยกเลิกงานโดยไม่ให้รางวัล สามารถชวนใหม่ได้
- เซฟเก็บผลสำเร็จ สมุด และความทรงจำ แต่ไม่เก็บตำแหน่ง/เส้นทางเดิน/งานที่ยังไม่เสร็จ โหลดเซฟแล้วต้องชวนใหม่ เริ่มเกมใหม่จึงเล่นกิจกรรมซ้ำได้
- ปฏิกิริยาการสำรวจแต่ละแบบเกิดครั้งเดียวต่อเซฟและต้องอยู่ใกล้กัน ข้อความที่ผู้เล่นหรือ AI พิมพ์ไม่ถือว่าได้สำรวจสำเร็จ
- ห้อง 02–03 ไม่เปิดระบบนี้เอง
- คำสั่งต้องคุยกับ NPC ตัวนั้น อยู่ห้องเดียวกันและใกล้กัน กิจกรรมต้องผ่านเงื่อนไขและผู้เล่นอยู่ใกล้ตำแหน่งงาน คำชวนไม่ข้ามเมนู/สมุด/คีย์แพด/หน้าต่างไอเทม
- การรับคำชวนเปลี่ยนเฉพาะโหมด/งานที่อนุญาต งานและการเดินยังพักระหว่างสนทนา ปิดบทสนทนาจึงเริ่มเดินหรือสะสมเวลาจริง ข้อความตอบของ AI เองเริ่มงานไม่ได้
- ตัวแยกคำชวนเป็นกติกาภาษาไทย/อังกฤษแบบจำกัด ไม่ใช่ AI เข้าใจคำสั่งได้ทุกประโยค หากขอหลายอย่างพร้อมกันหรือระบุหลายกิจกรรมจะขอให้ชวนทีละอย่าง ไม่มีข้อความคำสั่งสำเร็จรูปให้กด
- การแยกรายวรรครองรับเครื่องหมายวรรคตอน/ขึ้นบรรทัดใหม่ และคำเชื่อมที่กำหนด เช่น “แต่” / “but” ส่วน “แล้ว/และ” แยกการกระทำหลังตรวจคำถามของวรรคนั้นแล้ว ไม่ตีความสองส่วนของคำถามเป็นคำสั่ง คำพูดอ้างอิงหรือสมมติในข้อความยังกันทั้งข้อความไว้ก่อนอย่างระมัดระวัง ถ้าต้องการสั่งจริงให้ส่งคำขอแยก ไม่รับประกันประโยคยาวที่ไม่มีขอบเขตชัดเจนทุกสำนวน

## ให้เพื่อนต่อยอด

ข้อมูลอยู่ที่ `Assets/Data/Companions/Room01_Companion.asset` เชื่อมผ่านช่อง `companionScenario` ของ `RoomKnowledgeData`

สร้าง `Game/Companion Scenario` ใหม่เพื่อปรับ NPC, ขอบเขตเดิน, ระยะห่าง, ตำแหน่งสองฝ่าย, เวลาช่วยงาน, บทพูด และปฏิกิริยาตาม `interactionId` โดยไม่เขียนสคริปต์เฉพาะตัวละคร กิจกรรมใช้ conditions เดิมของ framework

ค่าความรู้สึกในการเดินและ UI อยู่ใน asset เดียวกัน: `moveSpeed=2.6`, `moveAcceleration=6.5`, `moveDeceleration=8`, `followStartBuffer=0.45`, `walkAnimationPace=0.55`, `activityLabelDistance=2.4` ปรับผ่าน Inspector ได้ ระยะหยุดหลักยังเป็น `followDistance=1.6` การเดินตามช้ากว่าผู้เล่นจึงมีช่วงเดินตามหลัง ไม่เร่งเกินค่าที่ตั้งหรือเทเลพอร์ตเพื่อไล่ทัน

เมื่อเพิ่มกิจกรรม ให้ตั้งชื่อ `title` และ `gameplayTerms` เป็นชื่อเรียกอื่นทั้งไทย/อังกฤษที่ AI อาจใช้ (เช่น กล่อง / box) ชื่อกิจกรรมจะถูกตรวจเสมอ ชื่ออื่นเหล่านี้จำกัดเฉพาะห้องและ NPC ที่เปิดใช้ scenario นี้ และต้องอ้างผ่าน fact ไม่ใช่แต่งข้อเท็จจริงเอง

ใส่ `instructions` เป็นวิธีร่วมมือของกิจกรรมเสริมโดยไม่ปนคำใบ้ปริศนาหลัก ไม่อ้างว่าเริ่มงานแล้ว และให้ตรงกับตำแหน่ง/เวลาที่ตั้งไว้ เกมเปิดเผยคำแนะนำเมื่อเงื่อนไขกิจกรรมพร้อมและยังไม่สำเร็จเท่านั้น หากเว้นว่าง คำถามจะตอบสถานะที่ยืนยันได้อย่างเดียว ส่วนคำชวนให้ลงมือยังเริ่มงานที่ผ่านเงื่อนไขได้

เส้นทางคำสั่ง: `DialogueManager.SendTypedMessage` → `CompanionDialogueCommands` (แยกคำชวน) → `NpcCompanionController` (ตรวจ NPC/ห้อง/ระยะ/เงื่อนไข) ส่วน AI และตัวสร้าง knowledge อ่านสถานะเท่านั้น เมื่อเพิ่มสำนวนให้เพิ่ม regression test สำหรับคำขอจริง คำถาม คำปฏิเสธ และคำพูดอ้างอิงคู่กัน ไม่เพิ่มระบบรันคำสั่งจากข้อความที่ AI ส่งกลับ

หลังแก้ข้อมูลใช้เมนู **Mystery Game → Validate Content** และรัน `CompanionTests` / `Room01CompanionTests` / `CompanionSpeechActRegressionTests` / `CompanionSpeechActPlayTests` / `CompanionQualifierRegressionTests` / `CompanionQualifierPlayTests` / `CompanionPresentationTests` / `CompanionPresentationPlayTests` ก่อนส่งต่อให้รัน EditMode และ PlayMode ทั้งหมดด้วย ควรทดสอบเดินจริงอีกครั้งเมื่อย้ายเฟอร์นิเจอร์ เพราะข้อมูลตำแหน่งต้องอยู่ในพื้นที่เดินได้

นี่เป็นต้นแบบกลไกสองฝ่ายและภาพกล่อง 2D แบบเรียบง่าย ยังไม่ใช่ NPC ที่หยิบ/ใช้สิ่งของใดก็ได้ ไม่ได้เพิ่มชุดภาพเดินใหม่ และยังไม่รวมระบบปริศนาหลายขั้นหรือการทดลองกับ API จริง
