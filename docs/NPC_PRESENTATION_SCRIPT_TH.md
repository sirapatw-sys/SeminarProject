# บทพูดนำเสนอ NPC คู่ร่วมแก้ปัญหา — 5 นาที
สถานะ: บทพูดพร้อมใช้กับต้นแบบ offline; ถ่ายภาพ/คลิปจาก build ที่นำเสนอจริงตาม ROOM01_DEMO_RUNBOOK_TH.md
ตัวเลขเวลาเป็นกรอบซ้อม ไม่ใช่ผลจับเวลาผู้พูดจริง

## 0:00–0:35 — ปัญหาและผู้ใช้
ภาพ: ผู้เล่นกับ Alice ใน Room01 และหลักฐานคนละชิ้น
ข้อความบนภาพ: “คิดและลงมือร่วมกัน”

“เราอยากให้การติดอยู่ในห้องปริศนารู้สึกเหมือนมีเพื่อนช่วยกันหาทางออกค่ะ ผู้เล่นต้องได้คิดเอง แต่มีอีกคนที่สังเกต ช่วยลงมือ และคุยจากสิ่งที่เกิดขึ้นจริง โครงการนี้จึงมีทั้งเกมตัวอย่าง และโมดูลร่วมคิดที่ทีมพัฒนาเกมปริศนาสามารถนำไปต่อได้”

## 0:35–2:05 — เดโมความร่วมมือ
ภาพ: เกมจริงเป็นหลัก ให้คนดูเห็นการพิมพ์ การเคลื่อนที่ และผล interaction

ก่อนขอช่วย:
“ผู้เล่นเป็นคนขอให้ Alice ช่วย ถ้ายังไม่ชัดว่าจะให้ช่วยตรงไหน เธอจะถามกลับ เราตอบชื่อสิ่งของต่อจากคำถามได้”

ระหว่างเดินช่วย:
“เมื่อคุยเสร็จ เธอเดินไปจับกลไกจริง งานยังไม่สำเร็จจนกว่าผู้เล่นจะทำอีกด้าน สิ่งที่ตัวละครพูดจึงต้องตรงกับสิ่งที่เกมทำ”

ระหว่างแลกข้อมูล:
“ข้อมูลที่ผู้เล่นพบไม่ได้กลายเป็นสิ่งที่ Alice รู้ทุกอย่างทันที เราต้องให้เธอเห็นหรือแบ่งปันหลักฐาน แล้วจึงเสนอแนวคิดให้เธอช่วยพิจารณาได้”

หลังลองไม่สำเร็จ:
“ถ้าเธออยู่ใกล้และเห็นว่าลองแล้วไม่สำเร็จ เธอจะส่งสัญญาณชวนทบทวน เราจะเข้าไปคุยเมื่อพร้อมก็ได้ โดยยังเป็นคนเลือกว่าจะลองอะไรต่อ”

อย่ารอ event ที่ติด modal; ปิด keypad ก่อน และซ้อมเส้นทางเดียวกันจาก New Game ล่วงหน้า
หากเดโมติด ให้ใช้คลิปสำรองจาก build เดียวกันและบอกว่าเป็นคลิป หลีกเลี่ยงอ้างว่าผ่านการเล่นสดเมื่อไม่ได้เล่นต่อสำเร็จ

## 2:05–2:45 — สิ่งที่ทำให้เชื่อถือได้
ภาพ: ก่อนมีหลักฐาน / หลังมีหลักฐาน / ระดับช่วยที่ต่างกัน โดยระบุสถานะจริง
ข้อความบนภาพ: “รู้เท่าที่พบ • ช่วยตามที่อนุญาต”

“ระบบเกมเป็นผู้ยืนยันหลักฐาน ผลการกระทำ และระดับคำใบ้ ความสัมพันธ์กำหนดระดับความช่วยเหลือ แต่ไม่ได้ทำให้ตัวละครรู้ข้อมูลที่ยังไม่พบ คำตอบที่ดูมีเหตุผลจึงไม่ถือว่างานสำเร็จ ผู้เล่นยังต้องทดลองจริงค่ะ”

“ชุดสาธิตนี้ใช้ออฟไลน์ ส่วนการเชื่อม AI มีการตรวจด้วย provider จำลอง คุณภาพภาษาจากโมเดลจริงยังต้องวัดแยก”

## 2:45–3:30 — คุณค่าสำหรับผู้สร้างเกม
ภาพ: Room01 คู่กับ Repair Workshop พร้อมกรอบ shared reasoning core
ข้อความบนภาพ: “เปลี่ยนข้อมูล • ต่อกับเกมของคุณ”

“เราแยกโมดูลร่วมคิดออกจากห้องนี้แล้วค่ะ ในตัวอย่างอีกธีม ตัวละครช่วยพิจารณาปัญหาอุปกรณ์จากหลักฐานสายไฟกับสวิตช์ ผู้พัฒนากำหนดข้อเท็จจริง สมมติฐาน และบทตอบผ่าน profile ส่วนเกมของเขาดูแลการเดิน หน้าจอ เซฟ และการลงมือจริง มีคู่มือติดตั้งและต่อระบบพร้อมให้ลองค่ะ”

## 3:30–4:25 — หลักฐานและสิ่งที่กำลังพิสูจน์
ภาพ: สถานะตรวจอัตโนมัติ / รอผู้เล่น / รอผู้พัฒนาลองใช้
ข้อความบนภาพ: “ตรวจระบบแล้ว • เก็บผลประสบการณ์ต่อ”

“เราตรวจการทำงานและกรณีปฏิเสธด้วย Unity tests รวมถึงทดสอบโมดูลในโปรเจกต์แยกที่ไม่มี assets ห้องแรกแล้ว ผลและขอบเขตการตรวจอยู่ในเอกสารโครงการค่ะ”

“คำถามถัดไปคือ คนที่ไม่รู้คำสั่งจะกลับไปหา Alice เองไหม และอธิบายได้ไหมว่าเธอช่วยอะไร เราเตรียมทดลองกับผู้เล่นใหม่ 3–5 คน อีกฝั่งจะให้ผู้พัฒนาที่ไม่ได้เขียนระบบลองติดตั้งและสร้างปริศนาต่างธีม พร้อมวัดเวลาจริง ตอนนี้ยังไม่มีผลสองส่วนนี้ จึงยังไม่สรุปว่าเกมสนุกขึ้นหรือใช้ต่อได้ง่ายสำหรับทุกคนค่ะ”

เมื่อได้ผลจริงแล้ว ค่อยแทนย่อหน้าที่สองด้วยจำนวนคน เหตุการณ์ที่พบ และเวลาติดตั้งจริง พร้อมบอกกรณีที่ต้องมีคนช่วย

## 4:25–5:00 — ชวนลอง
ภาพ: ชื่อโครงการ พร้อมตำแหน่งเดโม/คู่มือที่ผู้ชมเข้าถึงได้จริง
ข้อความบนภาพ: “ลองสร้างคู่ร่วมคิดในเกมของคุณ”

“จุดที่เราอยากให้คนเห็นคือ NPC มีบทบาทร่วมกับผู้เล่น ทั้งข้อมูลและการลงมือ โดยผู้สร้างเกมยังควบคุมกติกาได้ เราเริ่มจากเกมปริศนา Unity และมีตัวอย่างให้ลอง หากคุณทำเกมประเภทนี้ ลองใช้โมดูลกับปริศนาของคุณ แล้วบอกเราว่าขั้นตอนไหนยังยาก เพื่อให้รุ่นถัดไปตอบโจทย์คนใช้จริงค่ะ”

ก่อนขึ้นนำเสนอ: ชี้ไปที่ไฟล์ local ได้สำหรับการเดโมในเครื่องเท่านั้น อย่าใส่ QR ดาวน์โหลดหรือ URL ที่ยังไม่ได้เผยแพร่/ตรวจการเข้าถึง
