# แก้ตามรีวิว: Token / บทคุยซ้อน / สิทธิ์สำรวจ

อัปเดตต่อเนื่อง: [แก้ตัวเลือกบริบทสำหรับคำคุยเล่นและคำขอธรรมชาติ](NPC_REQUEST_ROUTING_FIX_20261017_TH.md) หลังตรวจพบช่องโหว่ใน ScopeActions รุ่นด้านล่าง ผล build/ZIP ในรายงานนี้เป็นรุ่นก่อนการแก้ต่อเนื่องดังกล่าว

สาขา `codex/npc-cothinking` ต่อจาก `70024e4` ไม่เพิ่มฟีเจอร์หรือ AI local รอบนี้ แก้ปัญหาจากการอ่านโค้ดและยืนยันด้วย Unity tests ก่อน/หลัง ส่วนข้อ 4–5 ที่เพื่อนแจ้งว่าไม่ใช่ปัญหาไม่รื้อหรือเพิ่มความยากอีก

## ยืนยันปัญหาก่อนแก้

เพิ่ม regression 4 ข้อแล้วรันบน runtime เดิม: ทั้ง 4 ข้อล้มเหลวจริง (`Logs/NpcReview_20261017/Before.xml`) อีก 1 test ใช้วัด request เท่านั้น ไม่เรียก API

- คำทักทายมี action 114 รายการ และมี world schema/geometry ทั้งที่ไม่ได้ขอให้ทำงาน
- เปิดบทสนทนาภาพเต็มระหว่าง C เปิดอยู่ได้ โดย C ยังเปิดในเฟรมเดียวกัน ก่อน Update จะปิดให้
- worldIntent ว่างแต่ speechAct=chat สามารถลบ legacy inspect_together ที่เสนอถูกต้องได้
- สั่ง NPC ตรวจภาพวาดแล้วเกิด inspected_painting และ observation ของข้อมูลหลังภาพจริง

การเปิดภาพเต็มซ้อน C เป็นเส้นทางที่ยืนยันและแก้แล้ว ยังไม่อ้างว่าเป็นสาเหตุเดียวของทุกภาพ UI ซ้อนที่เพื่อนเห็น เพราะยังไม่มีภาพ/ขั้นตอนจากการเล่นจริงของเพื่อน

## เปลี่ยนอะไร

1. **บทคุยทั่วไปใช้ prompt สั้น** เก็บบุคลิก ความสัมพันธ์ ความลับที่อนุญาต และประวัติที่มีขอบเขต ไม่แนบแผนที่ เมนู action หรือ schema world ไปกับคำทักทาย และยังเรียก AI ตอบ ไม่ใช่แทนทั้งหมดด้วย local fallback
2. **คำขอลงมือแนบเฉพาะข้อมูลเกี่ยวข้อง** วัตถุหนึ่งชิ้นมี capability เดินเพียงรายการเดียว ทิศไปอยู่ใน worldIntent เมนูข้อความรวมวัตถุเป็นแถวเดียว ไม่ส่งพิกัด/ขอบ collider/ตัวเลือกเดินซ้ำ 6 ทิศ ชื่อเป้าหมายชัดแล้วไม่ส่งวัตถุอื่นทั้งหมด ข้อความที่ยังไม่รู้ว่าอ้างวัตถุไหนยังมีรายการแบบย่อให้โมเดลตีความได้
3. **legacy action ไม่ผูกกับค่า none ของอีก schema** เมื่อ worldIntent ไม่มี verb/target/reference จะไม่ลบ follow/help/search เพียงเพราะ speechAct เป็น chat/question/unclear/request ตัวตรวจการลงมือยังตรวจคำพูดจริงและเงื่อนไขเดิม คำถาม คำปฏิเสธ หรือสวัสดีไม่กลายเป็นคำสั่ง ส่วน active world ที่ผิดรูปแบบ/ขัดกันยังปัดตก
4. **ใช้ตัวตรวจเดิมร่วมกันสำหรับ C และภาพเต็ม** คำสั่งช่วย/ค้นหาที่ AI เสนอใน C ไม่ถูกปล่อยผ่านไปเป็นแค่ข้อความอีก แต่ผ่านกฎเดียวกับบทสนทนาเดิมก่อนให้ controller ลงมือ
5. **ภาพเต็มกับ C มีเจ้าของ UI คนเดียว** StartDialogue ทั้ง string และ DialogueData ปิด C/ยกเลิกคำขอค้างทันที ก่อนเปิดภาพเต็ม callback เก่าเริ่มงานไม่ได้ งานที่รับไว้ก่อนปิด C ยังคงอยู่และพักตาม modal เดิม
6. **ผู้เล่นเป็นผู้ทำขั้นหลัก** ปิด allowCompanionExecution ของ Painting_Data, Desk_Data, Desk_Margin และกันขั้นที่ประกาศใน room.steps ที่ InteractionSystem แม้เผลอเปิด opt-in อีก ลบรายการ auto-observe ข้อมูลหลักจาก world inspection การ search ไม่เปิดลูกศรที่ยังไม่ถูกค้นพบด้วยผู้เล่น/การประคองร่วมกัน ตัวละครยังดูภายนอก ช่วยจับ และเห็นผลจากการร่วมมือจริงได้

การอ่านหลักฐานที่ผู้เล่นยื่นให้ยังอ่านตามต้นฉบับ ไม่ล็อกการอ่านด้วยคะแนนความสัมพันธ์ ส่วนคำใบ้/การตีความ/เฉลยยังผ่านนโยบายเดิม ไม่ถือว่าหลักฐานที่ผู้เล่นพบจริงคือสิทธิ์ให้ AI แต่งคำใบ้เพิ่ม

## วัดขนาดคำขออย่างไร

ใช้ Room01 ใหม่ที่ความสัมพันธ์เริ่มต้น บริบทเสริมว่าง สร้างข้อความและ JSON ผ่าน BuildReplyPrompt/BuildCompatibleReplyRequestJson จริง ไม่ POST ไปบริการ ไม่พิมพ์คีย์หรือ prompt เต็มลงรายงาน ผลก่อนอยู่ Before.xml ผลฉบับสุดท้ายอยู่ PlayModeAccepted.xml

| ข้อความ | action ก่อน → หลัง | request ตัวอักษรก่อน → หลัง | UTF-8 bytes ก่อน → หลัง |
| --- | ---: | ---: | ---: |
| สวัสดี Alice | 114 → 0 | 25,132 → 3,291 | 47,872 → 7,921 |
| วันนี้เป็นยังไงบ้าง | 114 → 0 | 25,139 → 3,298 | 47,905 → 7,954 |
| ภาพวาดนั่น ฝากพิจารณารายละเอียดให้ที | 114 → 7 | 25,156 → 10,378 | 47,954 → 24,772 |

คำทักทายมี request ตัวอักษรลดประมาณ 86.9% และ bytes ลดประมาณ 83.5% **ไม่ใช่ตัวเลข token, โควตาหรือความหน่วงจริงของ KKU** ยังไม่ได้ใช้ tokenizer ของโมเดลหรือ usage จาก provider การย่อ input ไม่รับประกันว่าความหน่วงจะลดตามสัดส่วน เพราะขึ้นกับ output/model ด้วย ตาม [OpenAI Docs เรื่อง latency](https://developers.openai.com/api/docs/guides/latency-optimization)

บริบท C/ภาพเต็มและประวัติจริงอาจทำให้ request ใหญ่กว่าตัวอย่างนี้ จึงควรให้เพื่อนตรวจ usage จริงแยกอีกครั้งหลังใช้ build/source รุ่นใหม่ และอย่าใช้ค่า 6.5% เดิมไปคาดสัดส่วนหลังแก้โดยตรง

## วิธีลองหลังแก้

1. ใช้ New Game เพื่อแยก flags/ความรู้ที่มีจากเซฟก่อนแก้
2. คุยเล่น/ทักทาย Alice ทั้ง C และภาพเต็ม ต้องไม่เสนอให้สำรวจเอง ถ้าตั้ง AI อยู่ยังเป็นคำตอบจาก provider ตามปกติ
3. สั่งตรวจภาพวาด/โต๊ะ Alice ไปดูได้ แต่ผู้เล่นยังต้องกด E สำรวจเอง ไม่พบโน้ตหรือรู้ข้อความลับแทน
4. ชวนช่วยจับโต๊ะก่อนผู้เล่นตรวจ ความร่วมมือเดิมต้องยังทำงานและสำเร็จเฉพาะเมื่อผู้เล่นลงมือ
5. พิมพ์หยุด/เปลี่ยนงาน และลองคำถามหรือคำปฏิเสธ ต้องไม่เกิด action ที่ไม่อนุญาต
6. เปิด C แล้วเปิดบทสนทนาภาพเต็มจากระบบ ต้องมีผิวคุยเดียวทันที ไม่รอเฟรมถัดไป และข้อความ AI ที่มาช้าต้องไม่กลับมาเปิด/สั่งงานเก่า
