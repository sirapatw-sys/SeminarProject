# NPC พบหลักฐานแล้วอยากเล่าให้ผู้เล่นฟัง

## เป้าหมายและพฤติกรรม

ทำให้การสำรวจของ Alice มีผลกลับมาถึงผู้เล่นอย่างรับรู้ได้ แทนการให้ผู้เล่นเดาว่า NPC พบอะไรแล้ว โดยไม่เพิ่มปุ่มสั่งงานหรือหน้าต่างบังคับคุย

1. ผู้เล่นพิมพ์ขอให้ค้นรอบห้อง หรือช่วยจับโต๊ะตามเส้นทางเดิม
2. NPC ต้องไปทำงานจริงและมี observation ของหลักฐานที่เกมเปิดเผยแล้ว การอ้างว่าพบจากผู้เล่นหรือข้อความ AI ไม่เพียงพอ
3. หลังงานจบและข้อความสั้นเหนือหัวหาย แสดงฟอง `...` สีฟ้าหากยังมีสิ่งที่ไม่ได้รายงาน ไม่เปิดหน้าต่าง/หยุดเกมให้เอง แยกจาก `!` สีทองของ event
4. เมื่อผู้เล่นเข้าไปคุยตามปกติ NPC เล่าข้อเท็จจริงที่อนุญาตก่อน ไม่เกิน 3 รายการต่อครั้ง
5. จำว่าเล่าอะไรแล้วผ่าน GameState flags และเซฟเดิม รายงานซ้ำไม่ให้คะแนน ไม่เพิ่มหลักฐานหรือสมุดซ้ำ

คำถาม “เธอเจออะไรบ้าง” จัดสิ่งที่ยังไม่เคยเล่าก่อนสิ่งเก่า และบันทึกว่าเล่าเฉพาะรายการที่ตอบจริง การเรียกตัวสร้างคำตอบเพื่อประเมินอย่างเดียวไม่มีผลต่อ read receipts

## ขอบเขตความปลอดภัย

- ใช้เฉพาะ fact ที่ประกาศใน search spots / station ของ scenario ปัจจุบัน ผ่าน knowledge permission และ NPC มี observation จริง
- ไม่รายงานเฉลย ปริศนาคำแนะนำที่มีสิทธิ์เฉพาะ ข้อมูลถูกห้าม หรือสิ่งที่ NPC ไม่เห็น แม้ผู้เล่นจะรู้แล้วก็ตาม
- เกมเป็นผู้ประกอบรายงานจาก canonical statements ไม่ให้ AI สร้างเนื้อหลักฐานใหม่ ข้อความนำแก้ได้ที่ `CompanionScenarioData.discoveryReportLine` และผ่าน validation บทพูดเดิม
- อ่านรายงานได้เมื่ออยู่ในระยะและสถานะอนุญาตเท่านั้น ซ่อนสัญญาณใน modal/หน้าเริ่มเกม/ห้องอื่น
- ถ้ามี mini event เดิมรออยู่ ไม่แสดงสัญญาณซ้อนและ event มาก่อน การเปิด event ไม่ลบหลักฐานที่ยังรอรายงาน
- การค้นที่ยกเลิกก่อนพบจริงไม่สร้างสัญญาณ ขอบเขตคำสั่งค้นหายังเป็นรอบห้อง ไม่ใช่การค้นวัตถุเฉพาะจุด
- ไม่เปลี่ยนการจัดการข้อความหลายช่วงหรือคำใบ้ที่ผู้ใช้ให้พักไว้ และไม่ได้แยกระบบรายงานนี้เป็นแพ็กเกจอิสระจากเกมหลัก

## ลองเล่น

เปิด Room01 ใน Unity 2021.3.16f1 เริ่มเกมใหม่ เดินหา Alice แล้วพิมพ์ “ช่วยหาหลักฐานหน่อย” ปิดบทสนทนาและรอให้ค้นเสร็จ เมื่อข้อความชั่วคราวหายให้สังเกตฟอง `...` สีฟ้า แล้วเดินกลับไปคุย ข้อความใกล้ตัวจะบอกว่า “กด E เพื่อฟังสิ่งที่ Alice พบ” เธอควรรายงานสิ่งที่ตรวจพบก่อนทักตามปกติ คุยซ้ำหรือค้นซ้ำหลังฟังหมดแล้วต้องไม่ส่งสัญญาณเดิมอีก

อีกเส้นทาง: สำรวจภาพวาด → ขอ “ช่วยจับขอบโต๊ะหน่อย” → ปิดบทสนทนาและรอให้ช่วย → ผู้เล่นสำรวจโต๊ะจากอีกด้าน → ปิดหน้าต่างข้อมูล → คุยกับ Alice เธอเล่าลูกศรที่เห็น แต่ไม่สวมว่ารู้เลขโน้ตจนผู้เล่นเอาให้ดู และไม่บอกรหัสลิ้นชัก

## ปรับจังหวะต่อจาก 3deb9dc

- ข้อความเหนือหัวตอนค้นพบและหลังช่วยโต๊ะบอกสั้น ๆ ว่ามีเรื่องอยากเล่า ไม่แสดงรายละเอียดลูกศร/กลไกซ้ำก่อนบทสนทนา
- ไม่ตัดรายละเอียดในสมุด ไม่เปลี่ยน observation หรือสิทธิ์ข้อมูล และไม่บังคับให้ผู้เล่นต้องคุยจึงผ่านห้องได้
- ถ้ายังไม่ได้ฟังแล้วขอค้นซ้ำ สัญญาณรายงานเดิมยังคงอยู่ แต่ถ้าฟังหมดแล้วจะบอกว่ารอบนี้ยังไม่มีหลักฐานใหม่เพิ่ม
- สำนวนสั้นแก้ได้ผ่าน `discoveryFoundLine` และ `searchNoNewLine` ใน Scenario และผ่าน validation บทพูดเดิม
- รูปทรง/ความชัดเจนบนจอเป็นงานที่ยังต้องลองด้วยคน ไม่สรุปว่า visual QA ผ่านจากการตรวจค่า HUD หรือข้อความ focus
