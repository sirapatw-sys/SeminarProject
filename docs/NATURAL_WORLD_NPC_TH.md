# NPC รับคำสั่งและลงมือกับวัตถุใน Room01

งานต่อจาก `cb2b85e` บน branch `codex/npc-cothinking` วันที่ 16 ตุลาคม 2026

## วิธีลองเล่น

1. เปิด Room01 / New Game แล้วกด **C** เพื่อคุยระหว่างเล่น
2. พิมพ์ `ช่วยไปตรวจภาพวาดหน่อย` แล้วกด Enter ตัวละครเดินไปและตรวจจริง
3. พิมพ์ `ลองเช็คโต๊ะให้หน่อย` เมื่อพบข้อความหลังภาพแล้ว NPC จะตรวจโต๊ะจนพบโน้ต
4. พิมพ์ `ช่วยอ่านโน้ตให้หน่อย` เพื่ออ่านตัวเลขตามต้นฉบับ โดยไม่สรุปรหัสแทน
5. พิมพ์ `ไปยืนมุมล่างซ้ายหน่อย` / `ไปยืนข้างขวาของภาพวาด` / `หยุดก่อน`
6. พิมพ์ `ไปตรวจอันนั้นหน่อย` ขณะยังไม่มีบริบท NPC จะถามชื่อ แล้วพิมพ์ `ภาพวาด` ตอบได้
7. กด Esc ปิดช่องคุย งานที่รับไว้ยังทำต่อได้ เปิด C กลับมาอ่านผลได้

คำชวนเดิม เช่น `มาช่วยดูอันนี้ด้วยกันหน่อย` และ `ช่วยจับโต๊ะหน่อย` ใช้ผ่านช่อง C ได้ด้วย เมื่อเงื่อนไขกิจกรรมพร้อม NPC จะไปช่วยจับจริงตามระบบเดิม

ช่อง C ล็อกการเดิน/ปุ่มของผู้เล่นระหว่างพิมพ์ แต่ NPC ยังทำงาน ส่วนบทสนทนาเต็มภาพแบบเดิมยังพักการเดินตามพฤติกรรมเดิม

คำสั่งที่รู้จักและอ่านหลักฐานที่พบแล้วทำงานในเครื่องได้ การตีความถ้อยคำใหม่และบทสนทนาทั่วไปใช้ provider ที่ตั้งใน F10 ไม่ต้องมี provider ใหม่ ไม่บังคับติดตั้ง local AI

หากใช้ ZIP ต้องแตกไฟล์ทั้งหมดก่อนเปิด exe ตั้ง provider/model/key ใน F10 ตามคู่มือ AI เดิม ไม่มี key อยู่ในแพ็กเกจ

## โครงสร้างและการเพิ่มเนื้อหา

- `CompanionScenarioData.worldTargets`: ชื่อ/aliases/ID/scene object/จุดยืน/ความสามารถ/หลักฐานที่ตรวจพบได้
- `RoomWorldRegistry`: ผูกข้อมูลกับฉาก รองรับเพิ่มวัตถุด้วยข้อมูล ตรวจ ID ซ้ำในรายการ runtime และคืนเฉพาะเป้าหมายที่มองเห็นในห้องปัจจุบัน
- `CompanionWorldCommands`: คำสั่ง local, การอ้างอิงเป้าหมาย, ถามกลับ, menu IDs `world:<verb>:<relation>:<targetId>` ให้โมเดลเสนอ
- `NpcCompanionController` และ `CompanionTaskExecutor`: ผู้ขยับตัวละครมีเพียง controller เดิม งานมี timeout/recheck/cancel และผลยืนยัน
- `InteractionSystem.TryExecuteCompanion`: เงื่อนไขและ effects เดิม ปิดค่าเริ่มต้น ต้อง opt in `allowCompanionExecution` พร้อมข้อความผลสำหรับ NPC
- `CompanionChatPanel`: ช่อง C, serial cancellation, timeout, บริบทชั่วคราว, ประวัติข้อความ, รายงานผลจริง
- `CompanionDiscovery`/`NpcObservation`: NPC เรียนรู้เฉพาะ fact ที่ตรวจจริงและเปิดเผยได้แล้ว

เพิ่มวัตถุที่ใช้ความสามารถเดิม: ตั้งชื่อ scene object ให้ไม่ซ้ำ เพิ่ม definition ใน worldTargets ระบุจุดยืนปลอดภัย ตั้ง aliases และ allowInspect/allowOpen หากต้องเปลี่ยนสถานะให้ตั้ง allowCompanionExecution บน interaction ที่เกี่ยวข้องทุก stage และใช้ conditions/actions เดิม เพิ่ม discoveredFactIds ให้ตรงกับ room facts ไม่เขียนเฉลยไว้ใน visibleDescription

หากเป็นพื้นที่โล่ง ให้ sceneObject ว่างและตั้ง approachPoint ไม่ต้องสร้าง interaction ใหม่

## ขอบเขตของรุ่นนี้

- รองรับ Move, Inspect, Open ที่โลกกำหนด; จุดหมายคือวัตถุ พื้นที่ที่ลงทะเบียน และด้านซ้าย/ขวา/หน้าของจุดยืนวัตถุบนแกนจอ
- ไม่รับพิกัดอิสระจาก AI ไม่รับหลายคำสั่งต่อกันแบบทั่วไป ไม่สร้างความสามารถใหม่จากคำพูด
- เปิดวัตถุได้เมื่อ interaction opt in และเงื่อนไขผ่าน; ไม่กรอกรหัสจาก acceptedAnswers ไม่เปลี่ยนฉาก/จบเดโมเอง
- ผลของ actions ใช้ GameState/inventory ร่วมเดิม ไม่มี inventory NPC แยก
- การเพิ่มทักษะใหม่ เช่น ยกเฟอร์นิเจอร์ ยังต้องเขียน executor/animation ของทักษะนั้น
- ความแม่นยำต่อทุกสำนวนยังต้องวัดกับโมเดลจริง คำสั่งที่รู้จักในเครื่องสำเร็จไม่ได้พิสูจน์โมเดลเข้าใจภาษา
- ใน Room01 การเปิดลิ้นชักรหัสและประตูข้ามห้องยังเป็นงานของผู้เล่น ตัวอย่างเปิดโดย NPC ที่ผ่านการทดสอบเป็นวัตถุ opt-in ซึ่งไม่มี input puzzle/transition
- การ build และ PlayMode tests ไม่ใช่การตรวจภาพด้วยคนหรือการทดสอบ KKU จริง
