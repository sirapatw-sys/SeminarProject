# NPC เข้าใจเจตนาและพื้นที่ใน Room01

หลังรีวิว: รุ่นล่าสุดลด prompt และไม่ให้ NPC ทำขั้นสำรวจหลักเอง ดู [รายงานแก้ตามรีวิว](NPC_REVIEW_FIX_20261017_TH.md) รุ่น/ผลทดสอบที่บันทึกท้ายไฟล์นี้เป็นประวัติของ e58d66c

งานต่อจาก `bb94157` บน `codex/npc-cothinking` วันที่ 17 ตุลาคม 2026 ไม่เปลี่ยน provider/model/key และไม่ติดตั้งหรือฝึกโมเดล local

## วิธีลองเล่น

แตก ZIP ทั้งหมดก่อนเปิด exe แล้วเปิด New Game / Room01 กด C เพื่อพิมพ์คุยระหว่างเล่น NPC ยังเดินและทำงานระหว่างช่อง C เปิดอยู่

- `โซฟาอยู่ตรงไหน` — ตอบตำแหน่งจากฉากจริง ไม่เริ่มเดิน
- `ช่วยไปดูโต๊ะข้างโซฟาหน่อย` — ตรวจของตกแต่ง ไม่ค้นพบโน้ตของโต๊ะทำงานผิดชิ้น
- `ไปยืนด้านหน้าของโซฟาหน่อย` — หาพื้นที่เดินได้ด้านล่างของโซฟา ไม่ยืนทับเฟอร์นิเจอร์
- `ไปยืนตรงที่ว่างระหว่างโต๊ะกับประตูหน่อย` — เกมคำนวณจุดใหม่จากสองวัตถุ ไม่ต้องสร้าง POI สำหรับประโยคนี้
- `ไปยืนข้างหลังกลางห้องหน่อย` — ทิศหลังหมายถึงด้านบนของจอ
- `ภาพวาดนั่น ฝากพิจารณารายละเอียดให้ที` — ต้องใช้ AI ที่ตั้งค่าไว้ เพื่อแปลคำขอที่ไม่ขึ้นต้นตามตัวกรองเดิม
- เมื่อรับงานกับภาพวาดแล้ว ลอง `อันนั้น ฝากพิจารณารายละเอียดให้ที` — ใช้ focus จากงานก่อน ไม่เดาเป้าหมายเมื่อไม่มีบริบท
- `หยุดก่อน` — ยกเลิกทันทีโดยไม่รอ AI คำตอบที่มาช้าเริ่มงานเก่าไม่ได้

คำขอที่ AI แปลแบบใหม่ใช้ในบทสนทนาภาพเต็มได้ด้วย แต่ NPC เริ่มเคลื่อนไหวหลังปิดบทสนทนา ตามพฤติกรรม pause เดิม แนะนำ C เมื่อต้องการดูการลงมือระหว่างพูด

คำขอที่ local รู้จักและคำถามตำแหน่งแบบตรงทำงานโดยไม่ใช้โควตา ถ้อยคำใหม่ต้องมี provider ที่ใช้งานได้ การทดสอบ connection และส่งข้อความหา provider จริงใช้โควตาตามบัญชี ไม่มี key ในแพ็กเกจ

## สิ่งที่เปลี่ยน

1. โมเดลส่ง `worldIntent` แยก speechAct, verb, targetId, relation, referenceId ไม่ต้องผ่านรูปประโยคขึ้นต้นเดิมสำหรับเส้นทาง semantic
2. โมเดลไม่ส่งพิกัดหรือ effects เกมตรวจเป้าหมายที่มองเห็น ความสามารถ เงื่อนไขปัจจุบัน และเส้นทางเอง
3. แผนที่ Room01 เพิ่มจาก 9 เป็น 16 เป้าหมาย รวมโซฟา โต๊ะเล็ก ต้นไม้ กระถาง กองหนังสือ ชั้นวาง และตู้ริมผนัง เป็น metadata ของฉาก/ภาพพื้นหลัง ไม่ใช่ปริศนาใหม่
4. วัตถุ opt-in `useSceneGeometry` อัปเดตจุดเข้าใกล้ตาม transform และใช้ขอบ collider แบบไม่ใช่ trigger เมื่อมี ไม่สแกนฉากใหม่ทุกเฟรม
5. รองรับ at/near/left/right/front/behind และ between สองวัตถุ ตรวจพื้นว่างและเส้นทางจริง จุดทดแทนอยู่ใกล้จุดที่ต้องการไม่เกิน 1.2 หน่วยและไม่เปลี่ยนฝั่งเงียบ ๆ
6. คำถามตำแหน่งตอบจากข้อมูลที่มองเห็น ไม่มีสิทธิ์บอกตำแหน่งหลักฐานลับหรือเฉลย
7. แยกชื่อซ้อน เช่น โต๊ะข้างโซฟา ออกจากโต๊ะและโซฟา แต่ alias เดียวกันของคนละวัตถุยังถือว่ากำกวม
8. ยกเลิกงานเมื่อ target/reference ย้าย หาย ขนาดเปลี่ยน หรือ ID ซ้ำระหว่างทำงาน ไม่รายงานสำเร็จที่ตำแหน่งเก่า

## สัญญา provider และความปลอดภัย

- รูปแบบ Responses API มี nested object, fields required และ additionalProperties=false ตาม [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
- Chat-compatible provider เดิมได้รับคำอธิบาย JSON รูปแบบเดียวกันผ่าน prompt ไม่สมมติว่าทุกรายรองรับ strict schema
- `speechAct=request` เท่านั้นที่เสนอ world task ได้ คำถาม บทคุย คำปฏิเสธ และข้อความไม่ชัดเจนไม่ใช่ความยินยอม
- คำขอนอก world เช่น follow/help/read ใช้ companionAction เดิมพร้อม worldIntent แบบ inactive (`speechAct=none, verb=none, targetId='', relation=at, referenceId=''`) ป้องกัน schema ใหม่กลืนความสามารถเดิม
- ถ้า worldIntent ผิดรูปแบบหรือขัดกับ legacy action จะไม่ลองทำอีก action แทน ผู้เล่นระบุชื่อ/ทิศ/การตรวจชัดเจนแล้ว AI เปลี่ยนเป็นอีกวัตถุ/อีกฝั่ง/เปิดแทนตรวจไม่ได้
- GameState และ InteractionSystem ยังเป็นผู้ตัดสินผล ไม่ปลดล็อกลิ้นชักรหัส ไม่เปิดประตูข้ามห้อง ไม่เพิ่มคะแนนหรือหลักฐานจากข้อความที่โมเดลแต่ง
- Speech-act classifier ยังผิดได้ จึงไม่อ้างว่ารองรับทุกประโยค และยังมี safety veto สำหรับการปฏิเสธ สมมติ อ้างคำพูด และสถานะบางแบบ

## เพิ่มห้องหรือวัตถุอื่น

ใช้ CompanionScenarioData.worldTargets เดิม ตั้ง ID/title/aliases/visibleDescription และ sceneObject ที่ตรงกับวัตถุหรือ collider ของของตกแต่ง ถ้าติดอยู่ในภาพพื้นหลังให้ผูกกับ collider/metadata ที่ตำแหน่งนั้น ไม่ต้องเขียน script รายชิ้น

ตั้ง approachPoint เป็นพื้นปลอดภัยและเปิด useSceneGeometry เมื่อต้องการติดตามการเคลื่อนของ scene object พิกัดเริ่มต้นใน asset เป็น world-space ของฉากเริ่มต้น ส่วน runtime คำนวณ offset จาก transform เมื่อติดตั้ง ไม่ควรเปลี่ยน definition asset ขณะเล่น

เปิด allowInspect เฉพาะที่มีคำบรรยายตรวจจริง หากต้องเปลี่ยนสถานะให้ opt-in interaction พร้อม companionOperation เดิม ส่วนของตกแต่งไม่มี discoveredFactIds ไม่ใส่เฉลยใน visibleDescription/aliases/inspectLine

## ขอบเขตและการตรวจต่อ

- ยังไม่ใช่ vision model ที่รู้ทุก pixel ของพื้นหลังเอง สิ่งที่ไม่มี metadata จะยังไม่รู้จัก ไม่มีสิทธิ์เดาวัตถุ/จุดหมายใกล้เคียงแทน
- ยังไม่รองรับ raw coordinates การชี้เมาส์ ลากวัตถุ นั่งบนเฟอร์นิเจอร์ หรือทำหลายงานพร้อมกัน
- ทิศทั้งหมดอิงจอ ไม่ใช่ทิศตัวละครหัน ถ้าจุดหมายติดกำแพง/ไปไม่ได้จะปฏิเสธ ไม่ teleport
- between ต้องระบุสองวัตถุชัดเจน งานย้ายเป้าหมายระหว่างเดินจะยกเลิกและขอคำสั่งใหม่ ยังไม่ไล่ตามวัตถุที่เคลื่อนตลอดเวลา
- ต้องประเมิน provider จริงด้วยประโยคที่ผู้เล่นคิดเอง วัดเจตนา/เป้าหมาย/ทิศถูก อัตราถามซ้ำ เวลา และผลกระทำจริง โดยแยกจาก regression ที่ใช้ AI จำลอง

ตัวอย่าง negative gate ก่อนเดโม: `อย่าเปิดลิ้นชัก`, `เมื่อกี้เดินไปโซฟาแล้วใช่ไหม`, `สวัสดี`, `เปิดลิ้นชักยังไง`, `ไปหาตู้เย็น` ที่ไม่มีในห้อง ต้องไม่เปิด/เดิน/เปลี่ยน state เอง

หลักฐานทดสอบรอบนี้อยู่ใน `Logs/NpcSemanticWorld_20261017/` ไม่ใช้ผลก่อนแก้หรือจำนวน fixture เป็นคะแนนความเข้าใจภาษาของโมเดลจริง

ตรวจพบและแก้ความเข้ากันได้ของ Unity JsonUtility ที่อาจสร้าง nested worldIntent ว่างแม้ JSON ไม่ได้ส่งช่องนี้มา: parser แยกการไม่มี property (legacy) ออกจากการส่งข้อมูลผิดรูปแบบ โดยทดสอบข้อความที่เอ่ยชื่อ property ใน reply ด้วย

ผลชุด EditMode ฉบับที่แก้ parser แล้ว: `EditModeAccepted.xml` ผ่าน 1,296/1,296 failed=0 skipped=0 บน Unity 2021.3.16f1 เป็นการทดสอบ local/AI จำลอง ไม่ใช่การเรียก KKU จริง

ผลชุด PlayMode บน source ฉบับเดียวกัน: `PlayModeAccepted.xml` ผ่าน 348/348 failed=0 skipped=0 รวมทั้งสองชุด 1,644/1,644 เพิ่ม 32 กรณีจาก baseline 1,612 กรณี ตัวเลขนี้ไม่รวมการนับชุดย่อยหรือการรันซ้ำ

ยังไม่ได้เรียก KKU/provider จริง ไม่ใช้โควตาจริง และยังไม่ได้ตรวจภาพ/การเล่นด้วยคน ไม่อ้างผล FPS หรืออัตราความเข้าใจภาษาจริงจากชุดทดสอบนี้
